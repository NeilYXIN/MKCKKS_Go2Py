# Correctness methodology

The project assesses engineering correctness with three independent
comparisons. This provides reproducible evidence for the declared test domain;
it is not formal verification, a cryptographic audit, or a security proof.

The test-only Go oracle in `bridge/differential_test.go` builds parameters, CRS,
parties, secret/public keys, and evaluation keys through the protected upstream
public API. For each primitive it evaluates the bridge model and a separate
protected-upstream public operation on the same source ciphertext, decrypts
both with the normal upstream full secret-key set, and compares both real and
imaginary components with the clear expression. Normal upstream `MulRelinNew`
is explicitly compared with the bridge's operation-local hoisted path.
Distributed shares are aggregated from the exact same ciphertext and compared
with full-key decryption. The oracle never calls the bridge helper being tested
as its reference operation.

Both `PN14QP439` and `PN15QP880` cover private/public encryption, ciphertext and
plaintext addition/subtraction, integer/fractional/complex constants,
plaintext/ciphertext multiplication, normal versus hoisted relinearization,
no-op rescaling through the safe upstream in-place reference, level dropping,
full-slot composite rotation, maximum-level conjugation, partial and collective
decryption, and circuits through predictable level exhaustion. The Python
release matrix separately covers positive, negative, zero, wrapped, and signed
32-bit-boundary rotations, all dtypes, 1D/2D/3D/5D shapes, slot/chunk
boundaries, the `2**20` validated magnitude boundary, and 1/2/4/8 parties for
both presets. Pull-request CI runs pairwise tests; the manual release-candidate
workflow runs the focused high-cost matrix.

The manual release workflow is configured to run 250 deterministic PN14 and
150 PN15 circuits of
length 3–10, checking every intermediate step rather than only final outputs.
It also exhausts all ordered pairs of the supported operation families from
representative states, exercises multi-chunk chains with partially filled final
chunks, and makes approximately one fifth of generated circuits attempt a
documented invalid transition to prove failure atomicity. Failure records retain
the preset, seed, operation trace, clear values, level, scale, participants,
bounds, status, and serialized ciphertext needed for reproduction.

The precision formulas and reporting fields are defined in `precision.md`.
Normalized conformance vectors use formula-derived primitive bounds; wider
values and circuits propagate approximation error through the clear expression.
Reports retain preset, scale, level, depth, seed, dtype, shape, party count,
maximum component error, RMS error, and minimum precision bits. Bounds are not
automatically widened after failures.

Property tests cover real and complex arrays and metamorphic identities. Native
fuzzing has separate envelope, parameter, plaintext, ciphertext/share, and
checksum-preserving correctness-tracking targets so mutations reach payload
decoders. Comparator self-tests deliberately perturb values, scale, level,
participants, complexity, chunk count, magnitude/error bounds, and range status
to prove that the oracle detects each mismatch.
Malformed ABI behavior is exercised by a standalone C consumer, while race,
close/use, process-spawn, fork rejection, live-handle, retained-memory, and soak
tests cover lifetime behavior.

Repeated encryption must yield distinct artifact IDs and serialized ciphertexts
while decrypting within the same bound. This is only a randomization regression
test; it does not prove semantic security.

Local development provenance lives under `baseline/`. Local benchmark JSON is
disposable and ignored by Git; release-relevant performance and correctness
reports are generated by the manual release-candidate workflow and attached to
the corresponding GitHub release. Each report applies only to its recorded
commit and environment. A release is blocked by a recovered native
panic, differential mismatch, precision-bound failure, nonzero leaked-handle
delta, unbounded retained-memory trend, race report, malformed-artifact crash,
or failed clean encrypted workflow. A passing engineering matrix is not an
independent cryptographic audit.
